# paper-translate

学术论文 Markdown 翻译工具。将 paper-ingestion 产出的 `full_text.md` 翻译为目标语言（默认中文），同时 **100% 保留** 公式、代码、图片引用等结构。

## 核心原理：结构感知分段（Structure-Aware Segmentation）

### 为什么不用占位符？

早期版本采用 **标记 + 占位符** 方案：先将公式 `$E=mc^2$` 替换为 `⟦LATEX_INLINE_7⟧`，翻译后再还原。这有两个根本缺陷：

1. **上下文断裂** — LLM 看不到公式内容，翻译周围文字时可能丢失对公式的指代关系
2. **标记丢失** — LLM 有 8-12% 的概率丢弃标记/占位符，触发昂贵的重试

### 物理隔离 vs 指令保护

当前方案基于一个第一性原理：**不进入 API 的内容不可能被破坏。**

文档被解析为有序的 Block 序列，每个 Block 标记为"可翻译"或"不可翻译"：

```
原文:   [Text₁] [$$公式$$] [Text₂] [![img](path)] [Text₃]
         ↓ 翻译    ↓ 跳过    ↓ 翻译    ↓ 跳过        ↓ 翻译
API:    [Text₁]             [Text₂]                  [Text₃]
输出:   [译文₁] [$$公式$$] [译文₂] [![img](path)] [译文₃]
```

| 内容类型 | 保护方式 | 可靠性 |
|---------|---------|-------|
| 行间公式 `$$...$$` | 物理隔离 — 不进入 API | 100%，物理上不可能被修改 |
| 代码块 `` ```...``` `` | 物理隔离 | 100% |
| HTML 表格 `<table>` | 物理隔离 | 100% |
| 独立图片 `![](...)` | 物理隔离 | 100% |
| 分隔线 `---` | 物理隔离 | 100% |
| 行内公式 `$...$` | 留在文本中，指令保护 | ~99%（LLM 能看到公式上下文） |
| 引用标记 `[1]` | 留在文本中，指令保护 | ~99% |

关键洞察：行内公式 **故意不隔离**，因为 LLM 需要看到 `$x_0, x_1, \dots, x_T$` 才能正确翻译围绕它的句子。实测中，占位符方案曾导致关键 LaTeX 序列整段丢失，而当前方案零丢失。

## 翻译流水线

```
输入 Markdown
    │
    ├── 1. 提取 YAML frontmatter（保留不翻译）
    ├── 2. 移除 References 章节（不翻译参考文献列表）
    ├── 3. 提取标题 + 摘要（作为翻译上下文注入 system prompt）
    │
    ├── 4. 逐行解析为 Block[]
    │       Text / LaTeX / Code / Image / HTML / HR
    │       标记每个 Block: translatable=True/False
    │
    ├── 5. 将连续可翻译 Block 分组为 Chunk（≤ 8000 字符/组）
    │
    ├── 6. 并行翻译所有 Chunk（线程池，最多 24 并发）
    │       ├── 每个 Chunk 翻译后立即验证
    │       ├── Hard failure（公式 $ 或标题 # 数量不匹配）→ 拆分重试
    │       └── Soft failure（段落数/长度偏移）→ 记录警告，接受结果
    │
    ├── 7. 将翻译结果对齐回原始 Block 位置
    │       ├── 1:1 精确匹配 → 直接映射
    │       ├── 标题锚定对齐 → 以 # 标题为锚点拆分
    │       └── 比例长度分配 → 按原文长度比例分配译文
    │
    └── 8. 重组：可翻译 Block 用译文，不可翻译 Block 用原文
           输出 full_text_ch.md
```

## 翻译后验证

每个 Chunk 翻译完成后自动运行 4 项检查：

| 检查项 | 判定标准 | 失败处理 |
|-------|---------|---------|
| 行内 `$` 计数 | 译文与原文差异 > 2 | **Hard** — 拆分为子块重试 |
| 标题 `#` 计数 | 任何不匹配 | **Hard** — 拆分为子块重试 |
| 段落数比例 | 超出 0.7 ~ 1.3 范围 | Soft — 记录警告 |
| 长度比例 | 超出 0.3 ~ 1.2 范围 | Soft — 记录警告 |

Hard failure 最多重试 3 次（逐次将 Chunk 对半拆分）。如果仍然失败，接受 best-effort 结果。

## 增量缓存与断点续翻

使用 `--resume` 参数可启用 Chunk 级缓存：

```bash
# 长论文翻译中途 API 出错
uv run scripts/translate_paper.py /path/to/full_text.md --resume

# 重新运行：只翻译失败的 Chunk，已成功的直接从缓存读取
uv run scripts/translate_paper.py /path/to/full_text.md --resume
```

- 缓存文件：论文目录下 `.translate_cache.json`
- 翻译成功后自动删除
- 源文件、后端、目标语言、Chunk 大小任一变化均触发缓存失效

## 性能基准

测试条件：后端 (`gemini-3-flash-preview`)

| 指标 | 短论文 (65KB) | 长论文 (101KB) |
|-----|:---:|:---:|
| 翻译时间 | 27s | 35s |
| API 调用次数 | 6 | 10 |
| Token 消耗 | 30,613 | 65,812 |
| 估算成本 | $0.029 | $0.062 |
| 重试次数 | 0 | 0 |

相比旧版（标记+占位符方案）：速度提升 1.8-2.5x，成本降低 33-49%，重试归零。

## 配置参数

| 参数 | 默认值 | 说明 |
|-----|-------|------|
| `DEFAULT_MAX_CHARS_PER_CHUNK` | 8000 | 每个翻译 Chunk 的最大字符数 |
| `MAX_RETRIES` | 3 | API 调用失败重试次数 |
| `CHUNK_MISSING_RETRIES` | 3 | 验证失败后的 Chunk 拆分重试次数 |
| `MAX_WORKERS_CAP` | 24 | 并行翻译最大线程数 |
