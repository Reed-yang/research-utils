# research-utils

Academic research paper processing toolkit, driven by Claude Code agentic skills.

## Project Architecture

```
research-utils/             ← project root
├── paper-ingestion/        ← PDF → Markdown (Python script, uv-managed deps)
├── paper-translate/        ← Markdown paper translation (Python script)
├── paper-summary/          ← Structured summarization (SKILL.md only, Claude built-in)
├── paper-validator/        ← Paper review (SKILL.md only, Claude built-in)
└── subtitle-translate/     ← SRT subtitle translation (Python script)
```

### Two Types of Skills

- **Script-based** (paper-ingestion, paper-translate, subtitle-translate): have a `scripts/` directory, executed via `uv run`, require API keys
- **Built-in** (paper-summary, paper-validator): contain only SKILL.md, executed directly by Claude, no external dependencies

## Standard Workflow

```
paper-ingestion → summary → paper-translate → paper-validator
```

1. **paper-ingestion**: PDF/URL → `{YYYYMMDD}-{Title}/full_text.md` + `assets/` + `notes.md` (empty)
2. **summary**: reads `full_text.md` → writes `notes.md` + backfills keywords into YAML tags
3. **paper-translate**: `full_text.md` → `full_text_ch.md` (same directory)
4. **paper-validator**: reads .tex/.md → outputs peer-review feedback

## .env Configuration

Two-level loading, root takes priority:

```
load_env_file(_ROOT_ENV)   # research-utils/.env  (loaded first, setdefault locks values)
load_env_file(_LOCAL_ENV)  # skill-dir/.env        (fills in remaining keys)
```

All API keys are listed in the root `.env.template`. Key variables:

| Variable | Purpose | Used by |
|----------|---------|---------|
| `DEEPSEEK_API_KEY` | DeepSeek translation API | paper-translate, subtitle-translate |
| `TENSORBLOCK_API_KEY` | TensorBlock Forge API | paper-translate, subtitle-translate |
| `GLM_API_ID` / `GLM_API_KEY` | Zhipu GLM-OCR | paper-ingestion |

## Script Execution Conventions

All script-based skills follow the same pattern:

- Entry point: `uv run scripts/<script>.py` (requires `cd` into the skill directory first)
- Output: JSON to stdout (`{"status": "success", ...}` or `{"status": "error", ...}`)
- Dependencies: each skill has its own `pyproject.toml`, installed via `uv sync`

## Paper Directory Structure

Standard directory generated by ingestion:

```
{YYYYMMDD}-{Sanitized_Title}/
├── reference.pdf      # Original PDF
├── full_text.md       # Markdown with YAML frontmatter
├── full_text_ch.md    # Chinese translation (created by paper-translate)
├── notes.md           # Summary notes (populated by summary skill)
└── assets/            # Extracted images
```

## Notes

- Directory naming: `YYYYMMDD-` prefix + sanitized title, Windows-safe characters
- The summary skill backfills keywords into the `tags:` field in YAML frontmatter
- paper-validator targets top-tier conferences (CVPR/ICML/ICLR/NeurIPS etc.) with a peer-reviewer perspective
- subtitle-translate output files are suffixed with `_zh.srt`
